# 流转账本：完整产品方案

## 核心原则

1. 原币是主数据，交易金额和币种永远不被折算金额覆盖。
2. JPY 与 CNY 余额分别汇总，只有总资产和报表提供折算视图。
3. 换汇是资金转移，不是收入或支出。
4. 代购销售额不是利润；利润必须扣除商品成本、运费、手续费和其他费用。
5. 商品按买入批次和数量管理，允许一件商品分多次、以不同价格售出。
6. 充值、跑腿等无库存业务使用“服务订单”，不强制关联商品或回国周期。

## 最终产品形态

- Web：响应式 PWA，电脑左侧导航，手机底部导航。
- Android：先将 PWA 封装为 Trusted Web Activity；需要完整离线能力时迁移 Flutter 客户端。
- API：网页和安卓共用 REST/JSON API。
- 数据库：线上 PostgreSQL，单机版可使用 SQLite。
- 部署：Docker Compose 一键启动，数据库卷持久化。
- 登录：邮箱密码为主，Google 登录可选，保证中国大陆场景可用。

## 核心数据模型

- `users`：邮箱、密码哈希、显示名、本位币。
- `accounts`：账户名、币种、类型、期初余额。一个账户只有一个主币种。
- `transactions`：账户、收支方向、业务类型、原币金额、分类、日期与备注。
- `exchange_batches`：换出/换入账户、两侧原币金额、实际汇率、剩余金额。
- `exchange_allocations`：一笔支出与一个或多个换汇批次的实际分摊。
- `products`：商品主档。
- `purchase_batches`：买入数量、剩余数量、单价、原币、买入日期和可选回国周期。
- `sales`：对应买入批次、售出数量、价格、原币和平台费用。
- `proxy_expenses`：运费、平台费、关税和其他费用。
- `service_orders`：充值、跑腿等无库存业务。
- `trip_cycles`：可选回国周期；创建不强制开始时间，关闭时记录结束时间。

## FIFO 换汇规则

例：批次 A 用 100,000 JPY 换得 4,800 CNY（0.0480），批次 B 用 100,000 JPY 换得 5,000 CNY（0.0500）。支出 2,500 CNY 时，如果 A 剩余 1,800，则分摊 A 的 1,800 和 B 的 700，对应实际日元成本为 51,500 JPY。

数据库必须保留两条 allocation，不可只保存一个平均汇率。界面可以额外显示综合成本汇率。

## 利润规则

- 商品毛利：销售收入折算价值 − 已售数量对应商品成本。
- 经营利润：商品毛利 − 运费 − 平台费 − 关税及其他费用 + 信用卡返点。
- 汇兑损益：资金最终换回时的实际价值 − 原账面价值。
- 最终利润：经营利润 + 已实现汇兑损益。
- 未换回的外币只显示未实现折算，不计入已实现汇兑损益。

## 页面与操作

- 概览：JPY/CNY 资金池、库存成本、当月利润、最近流水。
- 流水：普通、代购和换汇统一时间线，支持筛选与批量删除。
- 代购：商品、批次、部分售出、服务订单、费用和回国周期。
- 账户：PayPay、信用卡、支付宝、微信、银行卡，按币种分组。
- 报表：商品毛利、经营利润、汇兑损益、库存周转、平台和品类。
- 设置：分类、汇率来源、FIFO/移动平均策略、导入规则、备份与导出。

新增和编辑对话框点击遮罩不得关闭，避免误触丢失输入。必填字段仅在提交失败后显示错误。

## 安全与导入

- CSV/Excel 导入支持字段映射，导入来源不写进交易备注。
- PayPay、信用卡和平台账单可建立自动分类规则。
- 金额使用整数最小货币单位，汇率使用高精度 decimal。
- 密码使用 Argon2id 或 scrypt；Cookie 使用 HttpOnly、Secure、SameSite=Lax。
- 每日备份；用户可随时导出 JSON 和 CSV。

## Codex 里程碑

### A：正式记账

账户 CRUD、流水 CRUD、余额、登录与数据隔离、PWA 安装。

### B：代购闭环

商品与买入批次、部分售出、成本分摊、服务订单、费用与返点。

### C：跨币种核算

换汇交易、FIFO 分配、原币/折算视图、商品利润与汇兑损益。

### D：日常使用

账单导入、数据导出与备份、Android 安装包、自动化测试、Docker 部署和升级迁移。
